### 5. GUI repair (06:15–06:45 UTC)

**Problema:** Container blender-gui in restart loop — `s6-overlay-suexec: fatal: can only run as pid 1`

**Causa radice:** Il Dockerfile imposta `ENTRYPOINT ["/opt/start-backend.sh"]` che:
1. Avvia il backend Python in background
2. Poi fa `exec /init` per passare a s6

Ma quando `start-backend.sh` è eseguito come servizio di s6 (non PID 1), la chiamata a `/init` fallisce perché `s6-overlay-suexec` può funzionare solo come PID 1.

**Fix:** Sostituito l'entrypoint in `deploy-server.yml` con inline bash:
```yaml
blender-gui:
  entrypoint: ["/bin/bash"]
  command: ["-c", "cd /app && /venv/bin/python -m app.api & exec /init"]
```

Questo avvia il backend in background e poi esegue `/init` come PID 1 (perché bash è PID 1).

**Fix permanente:** Il Dockerfile va modificato per non usare `start-backend.sh` o per corregge il loop. Attualmente il fix via `deploy-server.yml` è sufficiente.
